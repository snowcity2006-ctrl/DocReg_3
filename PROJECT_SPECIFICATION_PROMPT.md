# Полный промт на разработку системы «СЭД: Документооборот Орг»

Ты — ведущий системный архитектор и full-stack разработчик. Твоя задача — с нуля спроектировать и реализовать десктопно-ориентированную систему электронного документооборота (СЭД «Документооборот Орг»), оптимизированную для эксплуатации в корпоративной среде российских защищённых операционных систем (Astra Linux Special Edition 1.7 «Смоленск» / Alt Linux / РЕД ОС / Windows) как в виде автономного настольного приложения (Electron / Node.js runtime), так и в качестве клиент-серверного веб-приложения с единой многопользовательской базой данных, расположенной на сетевом диске (SMB/CIFS / NFS).

## РАЗДЕЛ 1. ОБЩЕЕ ОПИСАНИЕ И АРХИТЕКТУРА СИСТЕМЫ

1. **Назначение системы:**
   Централизованная регистрация, учёт, поиск, контроль исполнения и классификация входящей, исходящей и внутренней деловой корреспонденции, приказов, договоров, нормативно-распорядительных и организационных актов организации.
2. **Стек технологий:**
   - **Frontend:** React 18+, TypeScript, Tailwind CSS, Lucide Icons, Canvas-Confetti (для уведомлений о регистрации).
   - **Стилизация и темы:** Полноценная поддержка переключения двух тем (глубокая контрастная тёмная палитра `#171A21` / `#0F1115` и адаптированная светлая тема с гарантированной контрастностью `#0f172a` для комфортного чтения на экранах любого типа).
   - **Слой абстракции работы с ОС и файлами:** Модуль `electronBridge` / Node.js API с поддержкой как нативного десктопного режима (работа с файловой системой, запуск системных просмотрщиков `xdg-open` в Astra Linux, диалоги выбора файлов и папок), так и автономного веб-режима с прозрачным резервным хранилищем в `localStorage` / REST API.
   - **Формат базы данных:** SQLite 3 (с поддержкой WAL-режима и механизмов блокировок сетевых файловых систем) либо централизованный PostgreSQL / REST API с автоматическим резервным копированием в файл `.sqlite`.

### 2.2. Окно реестра («Перечень зарегистрированных документов»)

  - Рядом с заголовком размещается бейдж с общим числом документов (белый шрифт на синем фоне).
  - Справа в шапке расположены элементы управления:
    - Кнопка сброса геометрии и ширин столбцов к стандартным значениям (`RotateCcw`).
    - Кнопка разворачивания/сворачивания окна на полный экран (`Maximize2` / `Minimize2`).
    - Двойной клик по шапке переключает полноэкранный режим.
- **Двустороннее мышиное масштабирование окна реестра (Resize Engine):**
  - **По высоте:** Нижняя граница окна снабжена ухватистой интерактивной планкой (`cursor-row-resize`, высота 20-22px) с центральным индикатором захвата (`GripHorizontal`). Перетаскивание вниз увеличивает высоту окна, перетаскивание вверх — уменьшает высоту (вплоть до компактных 180px).
  - **По ширине:** Левая и правая границы окна оснащены активными зонами захвата шириной 14px (`cursor-col-resize`) с подсветкой при наведении. Окно можно свободно расширять до границ монитора (до 4000px) и сжимать в меньшую сторону.
  - **Угловые маркеры:** В нижнем правом (`SE`) и нижнем левом (`SW`) углах расположены диагональные маркеры масштабирования (`cursor-se-resize` и `cursor-sw-resize`) для синхронного изменения и ширины, и высоты.
  - **Пропорциональное масштабирование столбцов:** При изменении ширины окна таблицы мышкой ширина абсолютно каждого из столбцов пропорционально масштабируется в большую или меньшую сторону (`newColWidth = startColWidth * (newTableWidth / initialTableWidth)`).
  - Во время перетаскивания отображается плавающий индикатор текущих размеров: `[Ширина × Высота px • Столбцы масштабируются пропорционально]`.
  - Все размеры и ширины колонок автоматически сохраняются в постоянную память (`localStorage` / конфиг) и восстанавливаются при повторном запуске.
- **Светлая тема в таблицах (Anti-Glare & High-Contrast):**
  - В светлой теме цвет шрифта в ячейках, заголовках столбцов, формах и справочниках принудительно переопределяется на глубокий тёмный цвет (`#0f172a` / `#1e293b`), исключая появление бледного или серого текста.
  - Чередование строк («зебра») с контрастными границами ячеек.
- **Индивидуальная регулировка колонок:**
  - На каждом разделителе заголовка столбца доступен ручной сплиттер (`cursor-col-resize`) для точечной подгонки ширины отдельной колонки.

## РАЗДЕЛ 3. СТРУКТУРА БАЗЫ ДАННЫХ И СПРАВОЧНИКОВ

### 3.1. Основная таблица документов (`documents`)
Каждая запись документа содержит следующий набор реквизитов:
- `id` (string / integer, Primary Key) — уникальный идентификатор записи.
- `docType` (string, Foreign Key -> `document_types.name`) — вид документа (например: *Приказ, Письмо, Служебная записка, Договор, Акт, Распоряжение, Протокол*).
- `direction` (enum: `'incoming' | 'outgoing' | 'internal'`) — направление документопотока.
- `outNum` (string, optional) — исходящий регистрационный номер.
- `outDate` (string ISO, optional) — дата исходящего документа.
- `inNum` (string, optional) — входящий регистрационный номер.
- `inDate` (string ISO, optional) — дата входящей регистрации.
- `subject` (string, required) — краткое содержание / тема документа.
- `sender` (string, optional, Foreign Key -> `correspondents.name` / `departments.name`) — корреспондент-отправитель.
- `recipient` (string, optional, Foreign Key -> `correspondents.name` / `departments.name`) — адресат-получатель.
- `executor` (string, optional, Foreign Key -> `employees.fullName`) — исполнитель / ответственное лицо.
- `status` (enum: `'draft' | 'registered' | 'in_progress' | 'executed' | 'archived'`) — статус исполнения.
- `dueDate` (string ISO, optional) — контрольный срок исполнения.
- `filePath` (string, optional) — локальный или сетевой путь к файлу скана документа или папке приложения (например, `/mnt/network_share/documents/2026/08/MCR-128_Agreement.pdf`).
- `sedUrl` (string, optional) — внешняя веб-гиперссылка на документ в вышестоящей государственной или ведомственной СЭД (ЕСЭДО, Госуслуги, СЭД Правительства и т.д.).
- `notes` (string, optional) — дополнительные служебные примечания.
- `createdAt` (timestamp) — дата и время внесения записи в систему.
- `updatedAt` (timestamp) — дата и время последнего редактирования.

### 3.2. Набор нормативно-справочной информации (НСИ / Справочники)
В системе реализован отдельный модуль управления справочниками с возможностью добавления, редактирования, удаления и синхронизации значений:
1. **Справочник видов документов (`document_types`):**
   - Поля: `id`, `name`, `code`, `defaultDirection`, `description`, `isActive`.
   - Предустановленные значения: Приказ по основной деятельности, Приказ по личному составу, Распоряжение, Входящее письмо, Исходящее письмо, Служебная записка, Договор, Дополнительное соглашение, Акт приема-передачи, Протокол совещания.
2. **Справочник контрагентов и организаций (`correspondents`):**
   - Поля: `id`, `name`, `fullName`, `inn`, `kpp`, `email`, `phone`, `address`, `isActive`.
3. **Справочник подразделений (`departments`):**
   - Поля: `id`, `name`, `shortName`, `headEmployeeId`, `phone`, `isActive`.
4. **Справочник сотрудников и исполнителей (`employees`):**
   - Поля: `id`, `fullName`, `position`, `departmentId`, `phone`, `email`, `isActive`.
5. **Справочник номенклатуры дел (`file_plans`):**
   - Поля: `id`, `index`, `title`, `retentionPeriod`, `notes`.

## РАЗДЕЛ 4. ТРЕБОВАНИЯ ДЛЯ РАБОТЫ В ASTRA LINUX 1.7 И ПРИ РАЗМЕЩЕНИИ БД НА СЕТЕВОМ ДИСКЕ

Данный блок является критически важным для стабильной промышленной эксплуатации в гетерогенных и защищённых контурах Astra Linux Special Edition 1.7 («Смоленск»):

### 4.1. Размещение базы данных SQLite на сетевом ресурсе (SMB / CIFS / NFS)
1. **Режим журналирования и блокировок (File Locking):**
   - В драйвере SQLite при работе через SMB/CIFS **запрещено** использовать стандартные ненадежные POSIX-блокировки.
   - Подключение должно инициализироваться с флагом `PRAGMA locking_mode = NORMAL;` и `PRAGMA busy_timeout = 5000;` (таймаут ожидания снятия блокировки при одновременной записи 5 секунд).
   - В зависимости от версии Samba-сервера journal_mode устанавливается в `PRAGMA journal_mode = WAL;` (если файловая система корректно поддерживает shared memory `*-shm`) либо fallback на `PRAGMA journal_mode = TRUNCATE;` или `DELETE;` для сетевых папок без поддержки shared memory primitives.
2. **Параметры монтирования сетевого диска в `/etc/fstab`:**
   Для исключения сбоев прав доступа и кодировок на рабочих местах Astra Linux сетевой каталог монтируется следующим образом:
   ```text
   //nas-server.corp/docflow_share /mnt/docflow cifs credentials=/etc/samba/cifs.cred,iocharset=utf8,file_mode=0775,dir_mode=0775,noperm,nobrl,mfsymlinks,nofail 0 0
   ```
   *Опция `nobrl` (no byte range locks) рекомендуется для Samba-шар, если несколько клиентов одновременно читают одну и ту же SQLite базу данных без взаимной блокировки процессами ОС.*
3. **Автоматическое резервное копирование (Backup Engine):**
   - Приложение содержит встроенный планировщик резервного копирования базы данных.
   - Механизм создаёт точечный слепок файла базы данных с отметкой времени в имени файла (например, `docflow_backup_auto_2026-09-10_12.00.00.sqlite`) в выделенный локальный или альтернативный сетевой каталог перед каждой сессией обновления.

### 4.2. Корректное открытие ссылок на документы (`filePath`) на разных компьютерах
1. **Унификация путей монтирования:**
   - На всех рабочих станциях сетевой диск монтируется в **единую стандартизированную точку монтирования** (например, `/mnt/docflow/documents/...`).
   - Приложение автоматически нормализует пути:
     - Заменяет обратные слэши Windows `\` на прямые слэши Linux `/`.
     - Распознаёт префиксы `smb://` и относительные пути от корня хранилища.
2. **Системный запуск файлов через `xdg-open`:**
   - Для открытия документа или папки в файловом менеджере Fly (Fly-FM / Astra Linux Desktop) используется системный вызов через платформенный мост:
     ```bash
     xdg-open "/mnt/docflow/documents/2026/file.pdf"
     ```
   - Если путь указывает на каталог — открывается файловый менеджер Fly с позиционированием на папке.
   - Если путь указывает на документ (`.pdf`, `.docx`, `.odt`, `.xlsx`, `.jpg`) — документ запускается в ассоциированном приложении (Astra Linux Fly PDF Reader, LibreOffice и др.).
3. **Защита от ограничений браузерной безопасности:**
   - При работе в веб-браузере ссылки на локальные пути `file:///` блокируются политикой браузера.
   - Система предусматривает локальный микросервис-прокси или Electron IPC метод `electronBridge.openPath(targetPath)`, который передаёт запрос доверенному процессу ОС, обходя ограничения веб-песочницы.

### 4.3. Совместимость с Мандатным Контролем Целостности (МКЦ) Astra Linux
- Все исполняемые файлы, фоновые скрипты и файлы базы данных должны создаваться с нулевым или соответствующим мандатным уровнем целостности, не требуя повышенных привилегий `root` для стандартных операций регистрации документов.
- Временные файлы блокировок и кэша создаются в стандартных пользовательских каталогах (`~/.config/docflow/` и `/tmp/`).

## РАЗДЕЛ 5. КРИТЕРИИ ГОТОВНОСТИ И ВАЛИДАЦИИ (ACCEPTANCE CRITERIA)

1. Полная компиляция и проверка статических типов без ошибок (`tsc --noEmit`).
2. При переключении в светлую тему весь текст в таблицах форм и реестров отчётливо читается на светлом фоне (`#0f172a`), а шапка реестра документов имеет фирменный синий цвет (`#2563eb`) с белым заголовком.
3. Окно таблицы документов изменяет ширину и высоту мышкой в обе стороны (больше/меньше); все столбцы пропорционально пересчитывают свою ширину без артефактов и горизонтального схлопывания.
4. Ссылка на файл на сетевом диске открывает скан-копию на любой рабочей станции под управлением Astra Linux 1.7 при совпадении точки монтирования сетевого хранилища.
